# 家庭使用与数据架构方案

日期：2026-11-05。状态：提案，未实施。上游基线见 [README](README.md)。

## 一、定位

目标是“可核查的数学知识地图 + 真实错题索引 + 少量复测”，不是未经审核的全自动老师、考试评分系统或智力测评。先验证一个实际在学的单元有帮助，再决定是否扩大。

目前等待教材版本、目录、已学章节，以及实际使用设备和跨设备同步需求。只需要与教学有关的最少信息；不要把真实儿童资料附到这个公开仓库。

## 二、分阶段计划

| 阶段 | 拟做事项 | 验收与停止条件 |
| --- | --- | --- |
| 0：本次 | Fork、固定检查基线、记录问题和方案 | 只提交文档；上游数据和代码零改动；不合并、不部署 |
| 1：待教材 | 用实际课本核对一个单元的知识点、前置关系、题目和答案 | 明确已覆盖、缺漏、未学、待核；没有教材不宣称完成适配 |
| 2：待授权 | 修正选定内容，建立审核状态，设计最小学习流程 | 逐题核对概念、条件、答案、解析；未经审核的题不进入儿童试用范围 |
| 3：待试用 | 受控使用少量不同类型题目，与家长/教师已有判断比较 | 能解释实际错因且无误教；不能只用答题次数或“掌握率”证明效果 |
| 4：再决定 | 扩充经审核的单元、复测方式及跨设备记录 | 以试用结果决定投入，不提前建设全年级平台 |

最小流程建议：选择已学单元 -> 少量题目与解题说明 -> 区分错误类型 -> 展示相关前置知识 -> 隔一段时间用不同题复测。家长/教师能够纠正题目或判定；“未知”“未学”“未测”“推断”保持可见。

## 三、能否不用本地数据库，直接读 Fork？

可以，但应把 GitHub 定位为版本化内容源，而不是所有数据的实时数据库。两类数据分开处理：

| 数据 | 建议位置 | 理由 |
| --- | --- | --- |
| 可公开的知识点、题目、依赖关系、教材映射、勘误 | 本 Fork，通过审阅后的提交维护 | 更新频率较低，可审查、版本固定、回退 |
| 孩子身份、答案、错题照片、学习进度、家长备注 | 不进入本 Fork；未来独立受保护的云端存储，或受控私密导出 | 涉及未成年人隐私、权限、删除和持续写入 |
| 公共内容缓存 | 应用内存或允许的客户端缓存 | 减少网络请求；不是要求在 Mac 安装数据库服务 |

不必在 Mac 上安装 MySQL/PostgreSQL 等数据库服务。如果还要求长期保存进度并跨设备同步，则需要一个独立、受保护的持久化层；可以是托管数据库配合服务端 API，不必是本地数据库。选型、服务账号、地区、预算和授权以后再定。

完全不建立任何数据库也能先做只读知识地图；如果只在当前会话保存答案，关闭后不保证保留。浏览器 localStorage/IndexedDB 或私密文件导出是其他方案，但它们仍是本地持久化，不能包装成“完全无本地存储”。是否允许缓存和私密导出待确认。

### GitHub 内容读取方案（尚未接入应用）

```text
上游固定版本
    -> 自有短分支修正和审核
    -> 审阅通过后合入 Fork 的 main
    -> 批准一个完整 commit SHA 作为内容版本
    -> 应用按同一 SHA 读取知识点、依赖和题目

学习记录 -> 独立受保护的数据服务（未来另行批准）
```

- 技术上可以读取分支文件，但分支头会变化，不适合把每次请求的“最新内容”直接当稳定教材。建议将分支解析为完整 commit SHA，同一学习会话的所有文件使用该 SHA，避免题库和知识点混用不同版本。
- 公开内容可不带凭据读取；例如当前固定基线的[知识点 JSON](https://raw.githubusercontent.com/kairyo/cn-math-taxonomy/972f9bbcf133a5aa5f7b6c1a74f44f7d48600e57/data/topics.json)。这只是数据入口示例，不代表内容已审核通过或应用已接入。
- 官方 Contents API 支持 `ref` 指定分支、标签或提交。当前全科 `questions.json` 为 8,554,248 字节，已超过该 API 普通 JSON/base64 内容读取的 1 MB 范围；若用 Contents API 获取它，应选 raw media type。也可评估固定 SHA 的 raw 文件读取。不能默认小文件接口对整库都同样适用。
- 未来可按学科/单元拆分经过审核的发布数据，减少启动时加载全部学科；本次不改文件结构或生成发布包。
- 只读 JSON，校验结构、版本与引用，不能执行内容中的脚本或把未经处理的字符串作为 HTML。服务端凭据不得放在浏览器、移动 App 包、URL 或公开仓库里。
- 考虑 HTTP 缓存/条件请求、有限重试、超时和上一份已验证版本。读取失败时明确提示内容版本和离线状态，不默默换成上游最新数据。
- 不在每道题作答后提交 Git；GitHub 的文件写入有版本冲突、API 限制和历史保留问题，不适合作为儿童学习事件数据库。
- GitHub 可访问性、浏览器跨域、缓存刷新、多设备网络体验和失败恢复尚未做应用级验证。不能承诺 raw 地址在所有网络中稳定可用，也不能把 REST API 限额套用为 raw 域名的 SLA。

### 后续若需要私密云端记录

仅列验收要求，不指定或开通供应商：家长身份验证、服务端授权、每个家庭的数据隔离、最少字段、加密传输、受控备份/恢复、删除策略和费用上限。前端不能直接持有 GitHub 管理令牌、数据库管理员密钥或服务端密钥。

学习记录应保存所用内容 commit SHA、topic/question ID 和必要的修订版本，保证将来修题后仍能解释历史结果。多设备写入需幂等标识、冲突处理和明确同步状态；照片等附件另行授权，不能混进公共内容。

## 四、先补内容与证据，不先堆功能

- 保留原始来源和稳定 ID，增加“未审核/已核题/教材已对齐”等明确状态及依据；这些字段还只是提案。
- 修正比例方向问题，同时核对生成来源和回退题，避免只改一个输出文件。
- 把“掌握（推断）”与实际测过区分；不能依据三题替代对理解、迁移和表达的评估。
- 题库补充以选定单元的变式和解释为主，不用 AI 大量生成替代人工复核。
- 移除与数学学习无关的外部测评入口，关闭非必要访问统计，再通过实际网络行为验证；本次未更改这些设置。
- 不发布课本扫描件，不把拥有教材当作可公开复制的许可；只接入允许使用的素材和自编题。

## 五、将来的验收清单

当前全部为 `NOT_RUN`，不因本次文档提交而视作通过。

- 实际教材单元与已学范围正确，无把未学内容当薄弱的情况。
- 题干、答案、解析、先修关系和难度标签经内容审核；原问题有针对性的反例测试。
- 内容版本一致，缺失/损坏/过期文件可识别；网络失败能明确停止或回退到经过验证的版本。
- 家庭版不产生未经批准的统计或测评外联；通过运行时请求检查，而不是只检查配置文本。
- 答题记录不进入公开 Git 历史；跨设备同步、权限隔离、删除和恢复按选定方案实测。
- 实际目标设备的阅读、输入分数、解释题和家长纠错流程可用；静态代码或截图不代替真实使用验收。

## 官方资料（2026-11-05 核对）

- [Fork 可见性](https://docs.github.com/en/pull-requests/reference/forks)：公开仓库的 Fork 同样公开，不存在单独私密的分支。
- [Contents API](https://docs.github.com/en/rest/repos/contents)：`ref`、公开资源免认证读取、raw 类型和文件大小限制。
- [REST API 限额](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)：请求需要考虑限额，不将仓库当高频业务写入接口。
- [REST API 最佳实践](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)：缓存/条件请求、减少轮询、处理限流。
- [凭据安全](https://docs.github.com/en/rest/authentication/keeping-your-api-credentials-secure)：最小权限，不把令牌写入代码或仓库。
